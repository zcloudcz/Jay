# CallType — Boti (Bots) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Samostatné zadání mimo betu 2026-09-16; nezačínat před uzavřením G1–G5 hlavního zadání. Nezávislé na plánu Channels (lze v libovolném pořadí).

**Goal:** Bot se v Jay chová jako běžný kontakt (Discord/Telegram styl): uživatel si ho přidá přes handle/QR a píše si s ním 1:1 nebo ve skupině. První bot: **Hermes Agent** (Nous Research, <https://github.com/NousResearch/hermes-agent>).

**Architecture (rozhodnuto zadavatelem 2026-09-17):** Bot je **E2E klient**, ne serverové Bot API. Je to běžné zařízení s `CT-XXXX-XXXX` handle a vlastními klíči; běží jako headless Dart proces, který přepoužívá existující `lib/core/crypto` a SignalR klienta. Server zůstává opaque relay a plaintext konverzace s botem nevidí. Bota provozuje jeho autor (plaintext vidí provozovatel bota — stejně jako u jakéhokoli protějšku).

**Tech Stack:** Dart (pure, bez Flutter SDK) pro bot runtime; server beze změny stacku.

## 0. Co stavíme (a co ne)

| | V rozsahu |
| --- | --- |
| Bot jako kontakt s odznakem „BOT“, 1:1 textový chat, E2E | ANO |
| Bot ve skupině (dostává skupinový fan-out jako každý člen) | ANO — odpovídá jen na zmínku `@handle`/odpověď, jinak mlčí |
| Most na Hermes Agent | ANO — první referenční bot |
| Serverové Bot API / webhooky s plaintextem na serveru | NE (porušuje E2E) |
| Slash příkazy, inline tlačítka, katalog botů, hovory s botem, přílohy | NE v první verzi |

## 1. Server (minimální změny)

- `Device.IsBot` (bool, default false) — nastavuje se při `POST /devices` polem `isBot`; neměnné. Migrace `AddDeviceIsBot`.
- `GET /devices/{id}/key-bundle` a handle lookup vrací `isBot`, aby klient ukázal odznak **před** přidáním kontaktu.
- Bot je pro rate limiting, frontu, TTL i push běžné zařízení (push token nemá → nic se neposílá). Žádný nový endpoint.
- `isBot` je samodeklarace, ne ověření. UI text: „Bot — zprávy čte automat provozovaný třetí stranou.“ Ověřené odznaky jsou mimo rozsah.

## 2. Bot runtime — `src/bots/calltype_bot/` (pure Dart package)

Zjištěno 2026-09-17: `lib/core/crypto/` nemá Flutter závislosti. Flutter-vázané jsou `storage/database.dart` (drift_flutter), `storage/secure_storage.dart` (flutter_secure_storage) a `signalr_client.dart` (jen `flutter/foundation.dart` kvůli `debugPrint`/`kIsWeb`).

- **B-krok 0 — vytěžení sdíleného jádra:** přesunout `core/crypto` + protokolovou část `api_client`/`signalr_client`/`session_manager` do pure Dart package `src/client/calltype_core/` (path dependency z Flutter appky). Rozhraní `KeyStore`/`SessionStore` už pokud existuje přepoužít; pokud je úložiště zadrátované na drift, zavést rozhraní jen v tomto bodě. `CallType-*` doménové řetězce se **nemění**.
- **Úložiště bota:** identita + sessions v jednom souboru šifrovaném klíčem z env `BOT_STORE_KEY` (AES-256-GCM, přepoužít backup crypto). Ztráta souboru = nová identita bota.
- **API runtime:**
  ```dart
  final bot = await CallTypeBot.start(apiBaseUrl: ..., storePath: ..., displayName: 'Hermes');
  print(bot.handle); // CT-XXXX-XXXX + QR odkaz do stdout při prvním startu
  bot.onMessage((msg) async => msg.reply(await backend(msg.text, conversationId: msg.conversationId)));
  ```
  Runtime řeší: registraci zařízení (`isBot: true`), doplňování OTK, příjem pre-key zpráv (session vzniká z první příchozí zprávy), ack, `RequestPendingMessages` po reconnectu, typing indikátor během generování odpovědi, idempotenci podle message UUID (LLM se nesmí zavolat dvakrát na replay).
- **Konverzační kontext** je věc backendu (Hermes má vlastní paměť); runtime předává jen stabilní `conversationId` (device ID protějšku nebo group ID).

## 3. Hermes most — `src/bots/hermes_bridge/`

- Tenký `main.dart`: `CallTypeBot` ↔ HTTP na Hermes gateway (`gateway/platforms/api_server.py` v repu Hermes; přesný kontrakt ověřit v H-kroku 0 — pokud je OpenAI-compatible `/v1/chat/completions`, použít ten a `conversationId` poslat jako `user`/session hlavičku).
- Konfigurace env: `CALLTYPE_API_URL`, `BOT_STORE_KEY`, `HERMES_URL`, `HERMES_API_KEY`, `ALLOWED_HANDLES` (allowlist protějšků; prázdné = jen vlastník — Hermes má nástroje a terminál, **nesmí** být otevřený komukoli s handlem).
- Nasazení: Dockerfile vedle Hermes (stejný host, Hermes API jen na localhost). Neběží v Azure App Service.
- Alternativa na později (mimo rozsah): nativní Python adaptér přímo v Hermes `gateway/platforms/` — vyžadoval by reimplementaci X3DH/Double Ratchet v Pythonu.

## 4. Klient (Flutter)

- Odznak „BOT“ u kontaktu, v hlavičce chatu a v náhledu při přidávání kontaktu; jednorázové upozornění při prvním otevření chatu s botem (text viz §1).
- Drift: sloupec `is_bot` v tabulce kontaktů (migrace schématu).
- Hovor na bota: tlačítka volání skrytá.

## 6. Přejímací kritéria

- **E2E:** server v DB ani logu nemá plaintext konverzace s botem (stejný test jako u běžných zpráv).
- **Idempotence:** replay téže zprávy nevyvolá druhé volání backendu ani druhou odpověď.
- **Perzistence:** restart bota zachová identitu i sessions; protějšek nevidí změnu safety number.
- **Allowlist:** zpráva od nepovoleného handle se zahodí bez volání Hermes.
- **UI:** odznak viditelný před přidáním kontaktu; text o třetí straně zobrazen.
- **Regrese:** vytěžení `calltype_core` nemění wire format — existující crypto testy beze změny zelené.

## 7. Rozhodnutí zadavatele (2026-09-17)

1. **Skupiny jsou ve v1** — přes existující per-člen fan-out (N šifrování na odpověď); nečeká se na Sender Keys. Bot odpovídá jen na zmínku/odpověď.
2. **Multi-device se neřeší** — 1 zařízení = 1 kontakt = 1 konverzace bota, stejně jako u běžných chatů.
3. **Odpověď přijde celá najednou** + typing indikátor. Žádné streamování, žádná editace zpráv v protokolu.
