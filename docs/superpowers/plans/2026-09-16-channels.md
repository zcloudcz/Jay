# CallType — Kanály (Channels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Samostatné zadání mimo betu 2026-09-16; nezačínat před uzavřením G1–G5 hlavního zadání.

**Goal:** Jednosměrné veřejné kanály ve stylu WhatsApp Channels: admin publikuje, sledující čtou v samostatné záložce, bez odpovědí a bez odhalení identity sledujících.

**Architecture:** Nová serverová entita `Channel` + `ChannelPost` + `ChannelFollower` vedle existujících skupin (skupiny se nepřepoužívají — kanál není konverzace). Obsah kanálu je **veřejný a nešifrovaný** (jediná výslovná výjimka z pravidla „server nevidí plaintext“); doručení přes existující SignalR hub (nová událost) + store-and-forward pro offline sledující. Klient: nová záložka **Aktualizace** vedle Chatů.

**Tech Stack:** stejný jako beta — .NET 10 minimal API, EF Core/Npgsql, SignalR, Flutter/Provider/Drift.

**Spec:** tento dokument. Vychází z rozlišení WhatsApp funkcí níže; zadavatel potvrdil, že požaduje **kanály**, nikoli broadcast list ani marketing API.

## 0. Co přesně stavíme (a co ne)

| Funkce WhatsApp | Chování | V CallType |
| --- | --- | --- |
| **Channels (kanály)** | Jednosměrný broadcast; vidí jen kdo kanál explicitně sleduje; záložka Updates, ne mezi chaty; sledující anonymní vůči adminovi i sobě navzájem; žádné odpovědi, jen emoji reakce a ankety; není E2E | **ANO — toto zadání** |
| Broadcast list | Zpráva přijde jako běžný 1:1 chat všem uloženým kontaktům (max 256) | NE (případně samostatné zadání „hromadná zpráva kontaktům“ nad existujícím E2E fan-outem) |
| Business Platform / Cloud API | Placené template zprávy s opt-inem, lze odpovídat | NE |

Důsledky pro CallType:
- Kanál **není konverzace**: nevzniká `Group`, žádná session, žádný ratchet. Zprávy kanálu se nikdy nemíchají do `chat_list`.
- Sledování je **explicitní akce** uživatele (odkaz `calltype://channel/<id>` nebo QR / vyhledání podle handle kanálu). Nikdo nezačne kanál sledovat automaticky.
- Server ukládá plaintext příspěvků a trvale (ne 30denní TTL fronty) — kanál má vlastní retenci (návrh: 90 dní, konfigurovatelné `Channels:PostRetentionDays`).
- Anonymita sledujících: server zná vazbu `ChannelFollower(ChannelId, DeviceId)` kvůli doručení, ale **nikdy ji nevrací** adminovi ani jiným sledujícím; API vrací jen agregovaný počet.

## 1. Datový model (server, PostgreSQL)

| Entita | Klíč | Sloupce |
| --- | --- | --- |
| `Channel` | `ChannelId` (Guid) | `Handle` (unique, `CH-XXXX-XXXX`, generováno jako user handle), `Name` (plaintext, ≤ 64), `Description` (≤ 512), `OwnerDeviceId`, `CreatedAt`, `FollowerCount` (denormalizováno, aktualizováno v transakci follow/unfollow) |
| `ChannelAdmin` | (`ChannelId`, `DeviceId`) | `Role` (`owner`/`admin`), `AddedAt` |
| `ChannelPost` | `PostId` (Guid, klient generuje pro idempotenci) | `ChannelId`, `AuthorDeviceId`, `Kind` (`text`/`image`/`video`/`poll`), `Body` (text ≤ 4096 nebo JSON ankety), `AttachmentBlobPath` (nullable, Blob nešifrovaný, limit 2 MiB obrázek / 16 MiB video), `CreatedAt`, `DeletedAt` (soft delete → klientům se pošle tombstone) |
| `ChannelFollower` | (`ChannelId`, `DeviceId`) | `FollowedAt`, `LastSeenPostAt` (pro badge nepřečtených) |
| `ChannelReaction` | (`PostId`, `DeviceId`) | `Emoji` (jeden grapheme z whitelistu 6 emoji), `CreatedAt` — API vrací jen součty per emoji |
| `ChannelPollVote` | (`PostId`, `DeviceId`) | `OptionIndex` — API vrací jen součty |

Index: `ChannelPost(ChannelId, CreatedAt DESC)`; `ChannelFollower(DeviceId)` pro „moje kanály“.

Retence: hosted service `ChannelPostCleanupService` (vzor `MessageCleanupService`) maže posty starší než `Channels:PostRetentionDays` včetně Blob objektů, dávkově.

## 2. API (minimal API, `Endpoints/ChannelEndpoints.cs`)

Vše `RequireAuthorization()` + rate limit `api`; identita z JWT, `deviceId` v URL nikdy nemění identitu (K01).

| Endpoint | Kdo | Účel |
| --- | --- | --- |
| `POST /channels` | kdokoli | založit kanál (`Name`, `Description`) → 201 `{ channelId, handle }`; limit 5 vlastněných kanálů na zařízení (`Channels:MaxOwnedPerDevice`) |
| `GET /channels/{idOrHandle}` | kdokoli | veřejný profil: name, description, followerCount, `isFollowing` pro volajícího. Bez seznamu sledujících. |
| `PATCH /channels/{id}` | owner/admin | název/popis |
| `DELETE /channels/{id}` | owner | soft delete kanálu; sledujícím přijde tombstone |
| `PUT /channels/{id}/admins/{deviceId}` / `DELETE …` | owner | správa adminů |
| `POST /channels/{id}/follow` / `DELETE /channels/{id}/follow` | kdokoli | idempotentní; 204 |
| `GET /channels/mine` | kdokoli | sledované + vlastněné kanály s počtem nepřečtených |
| `POST /channels/{id}/posts` | owner/admin | `{ postId, kind, body, attachmentBlobPath? }` → 201; opakování stejného `postId` = 200 bez duplicity |
| `GET /channels/{id}/posts?before=<ts>&limit=50` | sledující nebo admin | stránkování od nejnovějšího; obsahuje součty reakcí/hlasů a vlastní reakci/hlas volajícího |
| `DELETE /channels/{id}/posts/{postId}` | admin | soft delete |
| `PUT /channels/{id}/posts/{postId}/reaction` `{ emoji }` / `DELETE …` | sledující | jedna reakce na zařízení |
| `PUT /channels/{id}/posts/{postId}/vote` `{ optionIndex }` | sledující | jeden hlas na zařízení; změna hlasu povolena do `closesAt` ankety |
| `POST /channels/{id}/attachments` (multipart) | admin | upload nešifrované přílohy do Blob kontejneru `channel-media`, limit dle druhu, vrací `blobPath`; `GET /channels/{id}/attachments/{name}` streamuje jen sledujícím/adminům |

Chybové kódy: 403 nesledující/ne-admin, 404 neexistující/smazaný kanál, 409 limit vlastněných kanálů, 413 příloha nad limit, 422 nepovolené emoji / index ankety.

## 3. Doručování (SignalR + offline)

- Nová hub událost `ReceiveChannelPost` `{ channelId, postId, kind, body, attachmentBlobPath, createdAt, deleted }` — **plaintext**, žádný per-recipient ciphertext.
- Fan-out: server po `POST posts` odešle událost všem připojeným sledujícím (skupina SignalR `channel:<id>`; při follow/unfollow se připojení přidá/odebere ze skupiny, při reconnectu klient znovu volá `JoinChannels`).
- Offline: **žádná fronta per sledující** (u 10 000 sledujících by fronta explodovala). Klient si při startu/reconnectu stáhne `GET /channels/mine` a pro kanály s novými posty `GET posts?after=<lastSeen>`. Push: jedno obecné FCM upozornění „Nový příspěvek v kanálu“ per post, throttlované na max 1 push / kanál / 10 min (K04: bez obsahu).
- Jedna API instance: SignalR skupiny jsou v paměti, stejné omezení jako dnes.

## 4. Klient (Flutter, feature-first)

Nový modul `lib/features/channels/`:
- `channels_controller.dart` — seznam sledovaných/vlastněných, nepřečtené, follow/unfollow, načítání postů, reakce, hlasování; lokální cache v Drift tabulkách `channels`, `channel_posts` (plaintext, mimo šifrované tabulky zpráv).
- `updates_screen.dart` — nová záložka **Aktualizace** v hlavní navigaci (vedle Chaty, Kontakty); karta kanálu s posledním postem a badge.
- `channel_screen.dart` — feed postů (nejnovější nahoře nebo dole — držet se WhatsApp: nejnovější dole, scroll na konec), reakce (6 emoji), anketa s procenty po hlasování, žádné vstupní pole pro sledující; admin má compose bar.
- `channel_profile_screen.dart` — název, popis, počet sledujících, tlačítko Sledovat/Přestat sledovat, sdílet odkaz/QR (`calltype://channel/<handle>`).
- `channel_create_screen.dart` — založení + správa adminů (výběr z kontaktů).
- Router: deep link `calltype://channel/<handle>` → profil kanálu. Existující `qr_scanner_screen.dart` rozpozná kanálový QR (prefix) a přesměruje.
- UI musí u kanálu jasně říkat: „Příspěvky kanálu jsou veřejné a nejsou šifrované end-to-end.“ (K06/limity — nepředstírat E2E.)

## 6. Přejímací kritéria

- **Anonymita:** žádný endpoint ani hub událost nevrací `DeviceId` sledujícího/reagujícího/hlasujícího; test prochází všechny odpovědi a hledá cizí DeviceId → 0 výskytů.
- **Explicitní sledování:** kanál založený A se neobjeví u B, dokud B nezavolá follow; test.
- **Idempotence:** opakovaný `POST posts` se stejným `postId` → jeden řádek, jedna hub událost.
- **Oddělení od chatů:** post kanálu nikdy nevytvoří řádek v tabulce zpráv chatu ani položku v `chat_list`; test na klientu.
- **Retence:** post starší než limit je smazán včetně Blob; cleanup opakovatelný a dávkový.
- **Limity:** 413 nad limit přílohy, 409 nad limit vlastněných kanálů, 422 nepovolené emoji.
- **Push:** nejvýše 1 notifikace / kanál / 10 min, bez obsahu.
- **UI:** záložka Aktualizace, žádné vstupní pole pro sledující, viditelná informace o neexistenci E2E.

## 7. Rozhodnutí zadavatele (2026-09-17)

Tato rozhodnutí mají přednost před textem v §1–§6 výše, kde se liší.

1. **Retence 90 dní**, globálně přes `Channels:PostRetentionDays`. Parametrizace per zákazník/organizace je možná později (mimo rozsah v1) — neukládat retenci natvrdo jinam než do cleanup service.
2. **Bez videí ve v1** — `Kind` jen `text`/`image`/`poll`; příloha jen obrázek ≤ 2 MiB. Limit 16 MiB a `video` z §1/§2 neplatí.
3. **Objevitelnost jen odkaz / QR / handle.** Žádný katalog ani vyhledávání.
4. **Kanál smí založit jen zařízení s propojeným registrovaným účtem.** `Channel.OwnerAccountId` (místo spoléhání jen na `OwnerDeviceId`); vlastnická práva má každé zařízení propojené s účtem → kanál přežije ztrátu zařízení. `POST /channels` bez účtu → 403. Sledovat smí i anonym.
5. **Nahlásit + blokovat je součást v1 (C01/C03):**
   - `POST /channels/{id}/report` `{ postId?, reason }` (sledující; rate limit; 204) → entita `ChannelReport` + e-mail/log operátorovi (`Channels:ReportNotifyEmail`). Identita nahlašujícího se adminovi kanálu nikdy nevrací.
   - Blokace je čistě klientská: unfollow + lokální seznam blokovaných kanálů (Drift), blokovaný kanál nejde znovu otevřít z odkazu bez odblokování.
   - Operátor maže kanál přímo v DB / owner endpointem; admin UI pro moderaci je mimo rozsah.
   - Přejímka C04 rozšířena: nahlášení vytvoří záznam a notifikaci; blokovaný kanál zmizí z Aktualizací a nepřijímá posty.

## 8. Mimo rozsah

Videa, veřejný katalog kanálů, retence per zákazník, moderátorské UI, broadcast list („zpráva všem, kdo mají shop v konverzacích“), placené/marketingové zprávy s opt-inem, komentáře pod posty, přeposílání postů do chatů, multi-instance SignalR pro velké kanály, moderace obsahu nad rámec smazání adminem.
